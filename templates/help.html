EmailStore — how it works

EmailStore connects to a dedicated mailbox, downloads emails from approved senders, stores them locally in a SQLite database, and keeps the mailbox clean by deleting everything after processing.

Security policy

EmailStore operates on a zero-trust model — all emails are rejected by default unless they pass the configured security checks. Configure this in Settings → Security policy.

Security modes

Strict (default, recommended)
Requires both an authorised sender AND a valid token in the email. The safest option — only emails explicitly allowed from both directions are stored.
Balanced
Requires either an authorised sender OR a valid token. Useful when senders can't always add a subject tag but the token provides a second channel.
Relaxed
Requires only an authorised sender. No token needed. Simpler but relies entirely on the sender allowlist.

Token authentication

Tokens add a second factor — even if an authorised sender's address is spoofed, the attacker also needs to know the token. Tokens are set in Settings → Security policy.

Add the token to the email subject line using this format:

Invoice [ES:mysecrettoken] Q1 2026 → token mysecrettoken extracted and validated

Or use the X-EmailStore-Auth email header if your mail client supports custom headers.

Generate strong tokens with: openssl rand -hex 16

Size limits

Maximum email size, attachment count, and per-attachment size are all configurable. Emails or attachments that exceed the limits are rejected or skipped. Defaults are 10 MB per email, 5 attachments, 5 MB per attachment.

Receiving emails

EmailStore polls your dedicated mailbox on a timer (default: every 15 minutes). You can also trigger an immediate check by clicking Poll now in the inbox header or in Settings → Mailbox.

Every email goes through this pipeline:

  1. Check the sender — if the sender is not on your allowed list, the email is permanently deleted from the mailbox without being read further.
  2. Check for duplicates — already-stored emails are skipped and deleted from the mailbox.
  3. Parse the email — subject, plain text body, HTML body, and any attachments are extracted.
  4. Assign a category — the subject line is checked for a tag (see below) and against any keyword rules you have set up.
  5. Store and delete — the email is saved to the local database, attachments are saved to disk, and the email is deleted from the mailbox.

The mailbox is always left clean — every processed email (accepted or rejected) is deleted from the server.

Categories

Categories let you organise emails. The default categories are Inbox, Work, Personal, Finance, and Other. You can create, rename, and delete categories in Settings → Categories.

Each category has a slug — a short lowercase identifier. The slug is auto-generated from the name when you create it (e.g. "Q1 Reports" → q1-reports). You can see each category's slug in Settings → Categories.

There are three ways an email gets assigned to a category:

  • Subject line tag — automatic, highest priority (see below)
  • Keyword rule — automatic, checked if no subject tag matched
  • Manual — use the dropdown when viewing an email

Subject line tags

The easiest way to auto-categorise an email is to put the category slug in square brackets at the very start of the subject line:

[invoices] Q1 receipt from supplier → assigned to Invoices category
[work] Project Alpha update → assigned to Work category
[personal] Holiday photos → assigned to Personal category
No tag — just a normal subject → checked against keyword rules, or uncategorised

The tag is case-insensitive — [Invoices], [INVOICES], and [invoices] all work the same way. The slug must exactly match a category slug in your system.

Keyword rules

If no subject tag is found, EmailStore checks the subject against any keyword rules you have configured. A rule is a word or phrase — if the subject contains it (case-insensitive), the email is assigned to that category.

For example, if you add the keyword rule receipt to the Finance category, then any email with "receipt" anywhere in the subject will be auto-categorised as Finance — even without a subject tag.

Add keyword rules in Settings → Categories by selecting a category and entering the keyword pattern.

Allowed senders

Only emails from addresses on your allowed list are ever stored. Everything else is immediately and permanently deleted from the mailbox — the body is never read and attachments are never touched.

Addresses are matched case-insensitively. Manage your list in Settings → Allowed senders.

You can add a display name alongside each address — this is just a label for your reference inside EmailStore and has no effect on matching.

Polling

EmailStore polls the mailbox automatically on a timer. The default interval is 15 minutes. Change it in Settings → Mailbox under Poll interval.

Poll now triggers an immediate check without waiting for the timer. It's available in two places:

  • The inbox header — always visible at the top of the email list
  • Settings → Mailbox — useful right after changing connection settings

If a poll fails (connection error, wrong password, etc.) EmailStore uses exponential backoff — it waits 30 seconds, then 1 minute, then 2 minutes, up to a maximum of 30 minutes between retries. Successful polls reset the backoff.

Attachments

Attachments are downloaded and stored locally in data/attachments/, organised by email ID. When viewing an email, attachments are listed at the bottom — click any one to download it.

You can set a maximum attachment size in Settings → General. The default is 25 MB per attachment.

Settings reference

Mailbox
IMAP host, port, username, password, connection mode (TLS / STARTTLS / plain), poll interval, and debug logging toggle. Also has the Poll now button.
Allowed senders
The list of email addresses permitted to send emails to the store. Anything not on this list is deleted on arrival.
Categories
Create and delete categories, view their slugs (used in subject line tags), and manage keyword rules for automatic categorisation.
Security
Change the login password and configure the session timeout (how long you stay logged in before being asked to log in again).
General
Maximum attachment size limit.
Re-run setup wizard
At the bottom of the main Settings page. Logs you out and resets the setup flag so you can go through first-time setup again. Your stored emails are not deleted.

Gmail — step by step

  1. Enable IMAP — In Gmail go to Settings (gear icon) → See all settings → Forwarding and POP/IMAP → Enable IMAP → Save changes.
  2. Create an App Password (required if 2-step verification is on) — Go to your Google Account → Security → 2-Step Verification → App passwords. Create one named "EmailStore". Use this password in EmailStore instead of your normal Google password.
