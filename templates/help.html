EmailStore — how it works

EmailStore connects to a dedicated mailbox, downloads emails from approved senders, stores them locally in a SQLite database, and keeps the mailbox clean by deleting everything after processing.

Security policy

EmailStore operates on a zero-trust model — all emails are rejected by default unless they pass the configured security checks. Configure this in Settings → Security policy.

Security modes

Strict
Requires both an authorised sender AND a valid token in the email. The safest option — only emails explicitly permitted from both directions are stored.
Balanced
Requires either an authorised sender OR a valid token. Useful when senders can't always include a token but you still want a second layer of control.
Relaxed (default)
Requires only an authorised sender. No token needed. Simplest to use — just add a sender to the allowlist and emails start arriving.

Token authentication

Tokens add a second factor — even if an authorised sender's address is spoofed, the attacker also needs to know the secret token. Tokens are configured in Settings → Security policy.

Add the token to the subject line using this format — it can appear anywhere in the subject:

Invoice [ES:mysecrettoken] Q1 2026 → token mysecrettoken extracted and validated
[ES:mysecrettoken] Project update → also valid — token at the start

Alternatively use the X-EmailStore-Auth: yourtoken email header if your mail client supports custom headers.

Generate strong tokens with: openssl rand -hex 16

Size limits

Maximum email size (default 10 MB), maximum attachments per email (default 5), and maximum per-attachment size (default 5 MB) are all configurable. Emails or attachments that exceed these limits are rejected or skipped with a log entry — they will not silently disappear.

IP allowlist

You can restrict web access to EmailStore to specific IP addresses or subnets — for example, only your home network. Configure this in Settings → Security policy → IP allowlist.

Enter one or more CIDRs or bare IP addresses, comma-separated:

192.168.1.0/24 → allow any IP in the 192.168.1.x range
10.0.0.5 → allow exactly one IP address
192.168.1.0/24, 10.0.0.5, 172.16.0.0/12 → allow multiple subnets and IPs
(empty) → allow connections from any IP — no restriction

The filter applies to all connections — including the login page. If you set a subnet and then lose access, you will need to either connect from an allowed IP or edit the database directly to clear the setting:

sqlite3 data/emailstore.db "DELETE FROM settings WHERE key='allowed_subnets'"

IPv6 addresses and CIDRs are also supported (e.g. 2001:db8::/32).

Receiving emails

EmailStore polls your dedicated mailbox on a timer (default: every 15 minutes). You can trigger an immediate check by clicking Poll now in the inbox header or in Settings → Mailbox.

Every email goes through this pipeline:

  1. Fetch envelopes — sender, subject, and message ID are fetched for all messages in the mailbox (lightweight, no body downloaded yet).
  2. Duplicate check — already-stored message IDs are skipped. Duplicates are deleted from the mailbox without re-processing.
  3. Sender check — if the sender is not on your allowed list, the email is permanently deleted without being read further.
  4. Security policy check — the configured mode and token rules are applied. Rejected emails are deleted from the mailbox.
  5. Fetch body — only for emails that passed all checks. Full body is fetched by UID (stable across mailbox changes).
  6. Parse and categorise — subject, text body, HTML body, and attachments are extracted. Category is assigned via subject tag, keyword rule, or Inbox fallback.
  7. Store and delete — email saved to SQLite, attachments saved to disk, then the message is deleted from the mailbox.

The mailbox is always left empty — every processed message (accepted or rejected) is deleted from the server.

Categories

Categories organise your emails into named groups shown in the sidebar. The default categories are Inbox, Work, Personal, Finance, and Other. Create and manage categories in Settings → Categories.

Each category has a slug — a short lowercase identifier auto-generated from the name (e.g. "Q1 Reports" → q1-reports). Slugs are used in subject line tags and the URL.

Inbox is a protected category and cannot be deleted. All emails that don't match any other category are automatically placed in Inbox.

There are three ways an email gets assigned to a category, checked in this order:

  • Subject line tag — [slug] or [slug:days] at the start of the subject (highest priority)
  • Keyword rule — a word or phrase match against the subject
  • Inbox fallback — all unmatched emails land in Inbox

You can also manually reassign any email using the category dropdown when viewing it.

Subject line tags

Put a category slug in square brackets at the very start of the subject to auto-categorise the email when it arrives:

[work] Project Alpha update → assigned to Work category
[finance] Invoice from supplier → assigned to Finance category
[personal] Holiday photos → assigned to Personal category
No tag — normal subject → checked against keyword rules, then placed in Inbox

Tags are case-insensitive — [Work], [WORK], and [work] all work the same way.

Keyword rules

If no subject tag is found, EmailStore checks the subject against keyword rules. A rule is a word or phrase — if the subject contains it anywhere (case-insensitive), the email is assigned to that category.

Example: add receipt as a keyword for the Finance category, and any email with "receipt" in the subject will be auto-categorised as Finance even without a [finance] tag.

Add rules in Settings → Categories.

Auto-delete (email retention)

You can configure EmailStore to automatically delete emails after a set number of days. This keeps storage manageable for high-volume categories.

Setting retention per category

In Settings → Categories, each category has an Auto-delete after field. Enter the number of days to keep emails, or 0 to keep them forever (default).

Setting retention via subject tag

You can set retention directly from the subject line using the [slug:days] format. This sets the category's retain period to that value (if it isn't already set):

[inbox:30] Your receipt → inbox category → auto-delete after 30 days
[work:90] Q1 report → work category → auto-delete after 90 days
[finance:365] Annual statement → finance category → auto-delete after 1 year

EmailStore checks for expired emails at startup and then once every 24 hours. When emails are auto-deleted their attachment files are also removed from disk. The log will show event=expiry_complete deleted=N when emails are purged.

Setting a category back to 0 days in Settings → Categories stops future auto-deletion — emails already stored are not affected.

Allowed senders

Only emails from addresses on your allowed list are ever stored. Everything else is immediately and permanently deleted from the mailbox — the body is never read and attachments are never touched.

Addresses are matched case-insensitively. Manage your list in Settings → Allowed senders.

You can add a display name alongside each address — this is just a label for your reference and has no effect on matching.

Polling

EmailStore polls the mailbox automatically on a timer. The default interval is 15 minutes. Change it in Settings → Mailbox under Poll interval.

Poll now triggers an immediate check without waiting for the timer. Available in two places:

  • The inbox header — the Poll now button is always visible at the top of the email list
  • Settings → Mailbox — useful right after changing connection settings to verify they work

If a poll fails (connection error, wrong password, etc.) EmailStore uses exponential backoff — it waits 30 seconds, then 1 minute, then 2 minutes, up to a maximum of 30 minutes between retries. Successful polls reset the backoff timer.

Enable Debug logging in Settings → Mailbox to see the full raw IMAP conversation in the logs — useful for diagnosing connection problems.

Attachments

Attachments are downloaded and stored locally in data/attachments/, organised by email ID. When viewing an email, each attachment is listed at the bottom — click any one to download it individually.

You can set a maximum attachment size in Settings → General. The default is 25 MB per attachment. Oversized attachments are skipped with a log entry; the rest of the email is still stored.

The actual content type is detected by sniffing the file content (not by trusting the declared MIME type), which guards against content-type spoofing.

Downloading and deleting emails

Download

When viewing an email, the ↓ Download button exports the email for use outside EmailStore:

  • No attachments — downloads a standard .eml file that can be opened in any mail client (Outlook, Apple Mail, Thunderbird, etc.)
  • Has attachments — downloads a .zip file containing the .eml plus all attachment files together

Delete

Click the Delete button when viewing an email to permanently remove it from EmailStore. A confirmation dialog requires you to type the word delete before the action proceeds. This prevents accidental deletion.

Deleting an email also removes its attachment files from disk. This cannot be undone.

Settings reference

Mailbox
IMAP host, port, username, password, connection mode (TLS / STARTTLS / plain), poll interval in minutes, and debug logging toggle. Also has the Poll now button.
Allowed senders
The list of email addresses permitted to send emails to the store. Anything not on this list is deleted on arrival without being read.
Categories
Create and delete categories, view their slugs, set per-category auto-delete retention periods, and manage keyword rules for automatic categorisation.
Security policy
Security mode (strict / balanced / relaxed), token authentication settings, size limits, and the IP allowlist for restricting web access to specific subnets.
Password & session
Change the login password and configure the session timeout (how long before you are asked to log in again).
General
Maximum attachment size limit (applies globally, independently of the per-category security policy limit).
Re-run setup wizard
At the bottom of the main Settings page. Logs you out and resets the setup flag so you can re-run first-time configuration. Your stored emails and settings are not deleted.

Gmail — step by step

  1. Enable IMAP — In Gmail go to Settings (gear icon) → See all settings → Forwarding and POP/IMAP → Enable IMAP → Save changes.
  2. Create an App Password (required if 2-step verification is on) — Go to your Google Account → Security → 2-Step Verification → App passwords. Create one named "EmailStore". Use this password instead of your normal Google password.
